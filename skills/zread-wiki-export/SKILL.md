# 导出 Zread 仓库 Wiki

将 Zread 当前可访问的整套仓库 Wiki 保存为可阅读的本地 Markdown。默认一章一文件，附带 `index.md`；保留正文而不是生成摘要。

## 输入和输出

- 仓库：GitHub 仓库 URL、`owner/repo` 或 Zread 仓库/章节 URL。从链接提取仓库身份；章节 URL 仍表示导出该仓库全部章节，除非用户明确缩小范围。没有仓库信息时才询问。
- 保存目录：采用用户指定的绝对路径并遵守当前环境的存储规则；未指定时，在允许写入的工作目录内创建 `zread-wiki/<owner>/<repo>/<导出时间>/`。已有导出不覆盖，除非用户明确要求更新。
- 语言：保留站点当前正文语言；只在用户要求时切换，不自动翻译。

`index.md` 记录仓库、Zread 入口、导出时间及时区、页面显示的索引日期/commit（若有）、各章节的层级、源 URL、本地文件链接和导出状态。章节文件使用目录顺序号加 URL slug 命名，避免同名标题覆盖；每章包含标题、源 URL 和完整正文。

## 浏览器与访问

使用 **Computer Use / 浏览器自动化**，按当前环境的浏览器操作指引启动，导出全程复用同一任务空间与页面；已验证环境使用 `ego-browser` 技能与 TaskSpace。先读取页面快照，再以链接、按钮名称及 DOM 结构定位；录制里的元素编号、点击坐标、账号和仓库名称都不是固定参数。

若以后出现能够导出 **Zread 原文** 的专用连接器，可在核对结果覆盖面后使用；其他 Wiki 平台的工具不能替代 Zread。不要逆向私有 API、读取 cookie/token 或为了导出安装 Zread CLI。

1. 打开 `https://zread.ai/<owner>/<repo>`，核对页面显示的仓库身份。域名为 `zread.ai`，不是 `zread.com`。入口若转到搜索页，使用页面中“在这里粘贴Github仓库链接或者通过关键词搜索”的输入框填入仓库 URL，选择匹配仓库。
2. 需要登录时，把浏览器交给用户完成登录，再恢复同一任务；不保存账号标识、凭据或登录跳转参数。
3. 区分可读 Wiki、未索引、排队中和错误页。未索引时，仅在本次请求包含生成/索引授权时点击一次“现在索引”；否则报告需要索引并询问是否提交。排队或生成期间沿用当前任务检查实际状态，不重复提交、不点击“刷新仓库”重新生成。站点的预计耗时不是成功证据；按用户时限等待，无明确时限则观察至多 10 分钟后报告待完成和恢复入口。
4. 对 504、访问限制或生成失败，记录实际错误。检查页面状态后最多手动重试一次；仍失败就停止受阻部分，不把错误页当正文，也不改用其他 Wiki 平台冒充成功。

## 建立完整章节清单

从仓库的左侧章节目录收集，不从正文中的引用链接推断章节。

1. 展开所有折叠目录组；快照若只覆盖视口，使用全页快照并检查目录自身的滚动区域。将目录自身滚动到底，逐屏累计链接，展开新出现的分组，直到到达底部且不再出现新条目；虚拟化目录不能只读取最后一屏 DOM。记录目录层级、顺序、标题和实际 `href`。
2. 只保留该仓库的章节链接，排除站点导航、收藏、反馈、GitHub 源码引用和本页锚点。根据真实链接去重，不猜测章节编号或连续 slug。
3. 仓库根 URL 可能是“概述”的别名。比较页面标题、目录激活项和规范链接，将根页与对应概述章节合并，不重复导出。
4. 遍历时若发现新的目录分组或章节，将其加入清单。结束前再次展开目录核对，直到没有遗漏的章节链接。目录无法完整展开时不得声称整库导出完成。

## 逐章保存

复用一个页面，优先点击已加载目录中的章节链接进行站内跳转。实测直接导航章节 URL 偶发 504，而站内跳转仍可正常加载；不要因此更换数据源。每次等待目标章节标题与正文加载完成，核对当前 URL/目录激活项，防止单页应用切换时把上一章正文重复保存。

- 优先读取该公开章节页面自身返回的原始 Markdown。实测页面 HTML 的 `self.__next_f.push(...)` 数据片段包含以 `---\nslug:<章节 slug>` 开头的完整正文：通过浏览器 `page.fetch(当前章节 URL)` 读取公开文档，以 DOMParser 取得 script 文本，再用 JSON.parse 解码匹配的片段，不执行脚本、不调用私有 API。核对 slug、去重后的正文唯一性及与当前可见文章的标题、首尾和内容块一致性；取不到完整正文时才使用 HTML 转换。
- 从观察到的 DOM 找到文章正文容器并提取完整 HTML 或工具提供的 Markdown。不要硬编码未经检查的 CSS class，也不要直接将整页 `innerText` 当成 Markdown。排除全站导航、侧栏目录、Ask AI、反馈按钮等界面内容，保留文章内的来源引用。
- 原始 Markdown 只移除页面元数据和代码块外的站点专用标签（实测为 `CgxTip`，保留其内部文字），不改写正文或代码。仅需转换 HTML 时，使用成熟的 HTML 转 Markdown 工具（如 `markdownify` 或 Turndown）。先检查现有依赖；缺少时仅在允许的外置工作目录建立隔离转换环境，避免修改全局环境。不要自写通用 HTML 转换器或让模型重新表述正文。
- 保留标题层级、段落、列表、表格、代码块及语言标记、链接、图片说明和源码引用。转换前将相对链接/资源地址按该章节 URL 解析为绝对 URL。
- 图表若保留了 Mermaid 源码，则保存为 Mermaid 代码块；若只有 SVG/图片，保存可读取的图像资源到导出目录并在 Markdown 引用。实测 Mermaid 异步渲染且旁边的放大按钮也是 SVG，须等待并选择实际图表（如 `svg[role*="graphics-document"]`）；原文含 Mermaid 时即使站点渲染为空也完整保存源码，不捏造图片。SVG 用 XMLSerializer 序列化并检查 XML 可解析性，不能直接把可能含 HTML `<br>` 的 outerHTML 当 SVG 文件。无法提取的图表明确列为缺失，不凭视觉猜写、不静默丢弃。普通图片可保留绝对远程 URL；这样生成的 Markdown 不等于完全离线镜像。
- 每章转换后逐项对照提取的正文：标题、段落、列表项、表格单元格和代码内容均应保留，核对首尾正文完整且没有加载占位符；转换造成的空白与 Markdown 标记变化不算缺失。DOM 对照保留 details/summary 等折叠区标题；KaTeX 同时包含可见层、无障碍层和源码，按其 TeX annotation 比对一次，避免重复文本误报。章节内容先落盘，再更新索引状态。单章失败可继续其余章节，但最终标为部分完成，列明失败 URL 和原因。已有文件只在确认属于本次导出且允许更新时写入。
- 全部章节保存后，把指向已导出章节的内部链接改为对应相对文件路径；有锚点时核对它是否仍对应目标标题，无法保证时保留源链接。其他链接保持绝对源 URL。

## 验收与交付

完成条件是清单中每个独立章节都有对应、身份正确且通过逐章内容比对的正文文件，不是只创建目录或找到 Wiki 首页。

- 比较完整目录清单、成功文件和失败项；核对本地文件链接实际存在、没有重名覆盖、没有登录/错误/加载页混入。
- 回读首章、末章和含表格/代码/图表的代表章节，对照浏览器验证标题、首尾正文、代码换行与图表保存情况。结构或图表缺失必须计入限制，不能报告完整成功。
- 只报告本次实际检查的范围。正文属于页面标示的索引版本，不能声称反映仓库最新代码。
- 交付 `index.md` 的绝对路径链接、成功/总章节数、失败或缺失项，以及远程图片依赖等影响阅读的限制。结束自己创建的浏览器资源，保留用户原有标签页。
