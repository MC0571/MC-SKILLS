# 正文提取、转换与规则修复

配合 [SKILL.md](../SKILL.md) 的章节清单、保存与续导流程使用。本文件负责每章正文如何提取、如何比对，以及页面结构变化后如何修复规则；保存位置、Git 历史和导出进度沿用主流程。

## 确认当前章节与正文边界

复用当前浏览器会话与页面，优先点击已加载目录中的实际章节链接。直接导航失败而站内跳转成功时，继续读取同一来源，不据此更换站点。等待目标标题与正文加载完成，同时核对当前 URL、目录激活项和文章标题，防止单页应用跳转后保存上一章正文。

- 以目录实际 `href` 和页面规范链接确定源 URL、章节 slug 及别名关系，不猜连续编号或由标题生成 slug。仓库身份、正文语言和可见索引版本须与当前导出一致；没有版本标记时如实保留这一限制。
- 根据当前 DOM 识别文章容器。排除全站导航、侧栏目录、Ask AI、反馈和放大按钮等界面内容，保留文章内的来源引用。未经观察的 CSS class 不能成为提取依据，整页 `innerText` 不能直接充当 Markdown。
- 确认文章末尾已加载；工具截断、懒加载或分段返回时补齐各段，不能用当前视口代替全文。读取折叠区的完整子树或展开它，保留 `details/summary` 的标题与正文。
- 保留用于本轮比对的源 URL/slug、标题、首尾正文及有序内容块。登录页、错误页和加载占位符不算正文；连续章节出现相同正文时，先排查页面切换或载荷归属，不能直接当成合法重复章节。

## 优先取得原始 Markdown

先检查当前公开章节页面的 HTML 或已获准读取的数据是否携带完整原始 Markdown。浏览器工具已有能返回原文的读取能力时也可使用，但必须与当前页面逐章核对身份、语言、索引版本和正文，不能仅凭工具返回成功就采用。

### 按实际观察解码页面数据

只有实际观察到 `self.__next_f.push(...)`，且其中存在与目标章节匹配的 Markdown/slug 结构时，才使用这一提取方式。例如，解码后的字符串可能以 `---\nslug:<章节 slug>` 开头；这只是识别线索，不保证封装、字段、换行或框架以后不变。

1. 用浏览器支持的 DOM/HTML 读取能力取得当前公开文档。需要解析 HTML 时可用 `DOMParser`，从观察到的 script 节点取得文本，定位已确认携带正文的数据字面量。
2. 只对符合 JSON 格式的参数或字符串使用 `JSON.parse`，按实际封装逐层解码。不要执行 script、调用载荷中的函数，或用 `eval`、`Function` 解释数据；也不要全局替换 `\\n`、引号或反斜杠冒充 JSON 解码，以免破坏代码和 TeX。
3. 正文跨片段时，必须按观察到的数据顺序和边界完整重组。解码后确认首尾和完整正文，不能把截断字符串、框架控制记录或邻章数据拼成文章。
4. 按目标 slug 匹配并核对当前 URL/目录项、标题、首尾和内容块。重复载荷中的同一份正文可去重；出现多个不同候选时不能盲选第一份或最长一份，须确认哪份对应当前可见章节及版本。无法确认完整性或归属时改走文章 HTML 转换，并记录原始数据提取受限。

没有观察到上述模式时，不猜测其仍然存在；使用已经确认的其他原文来源或文章 HTML。公开 API 与读取请求的探索边界见最后一节。

### 原文只做必要清理

保留正文原有语言、顺序、措辞和 Markdown 结构，不摘要、翻译、重新表述或格式化代码。只移除已识别的页面元数据，以及代码块外已确认属于站点渲染包装的标签。例如，页面实际使用 `CgxTip` 时可去掉包装标签，保留内部文字与嵌套内容；不能全局删同名字符串或误删代码示例。正文中的 YAML、HTML、表格、代码和 Mermaid 也属于原文。

## 必须转换 HTML 时

取得完整文章 HTML 后，优先使用浏览器工具提供且能保留结构的 Markdown 转换能力，或成熟的 HTML→Markdown 工具，如 Turndown、markdownify。先核对现有依赖；确需补齐时遵守当前环境的存储规则并使用隔离转换环境，不修改全局环境。本流程不要求特定浏览器产品或 CLI，不自写通用转换器，也不让模型重述正文。

转换前，将相对链接和资源地址按该章节源 URL 解析为绝对 URL。保留正文内链接、图片说明和源码引用；不要把源码引用误判为需要导出的 Wiki 章节。

| 内容 | 转换与比对要求 |
| --- | --- |
| 标题、段落、列表 | 保留标题层级、段落顺序、列表类型、嵌套和逐项文字，不能只保留可见摘要。 |
| 表格 | 保留表头、行列顺序及每个单元格内容。Markdown 无法表达的合并单元格等结构可保留原 HTML，并核对可读性，不能扁平化丢失对应关系。 |
| 代码 | 从代码节点保留原始内容、缩进、换行和语言标记，避免复制按钮或行号混入。围栏不能被代码中的反引号提前闭合；不对代码做空白归一化。 |
| `details/summary` | 保留折叠区标题及全部正文，不能因默认折叠而遗漏。转换器丢失结构时保留对应 HTML，再核对内部块。 |
| KaTeX/公式 | 页面含 TeX annotation 时，以实际观察到的 `annotation[encoding="application/x-tex"]` 等源码节点为依据，保留行内或独立公式位置，并只转换、比对一次。不要叠加可见层、无障碍层和 MathML 的重复文本；没有可靠源码时不能凭显示字符猜写 TeX，无法保真则列为缺失。 |
| 链接、图片与引用 | 保留文字、说明和源地址；资源地址必须可追溯到当前章，不能拿别章的同名资源补位。 |

## Mermaid、SVG 与图片

先按正文位置识别实际图表，核对源码或资源与当前章节的对应关系。

- 有 Mermaid 源码就完整保存为 `mermaid` 代码块，包括原始换行和图表定义。即使站点渲染为空，也保留已有源码，不猜图像或补写节点。
- 只有 SVG/图片时，等待实际图表加载，保存可读取的图像资源到导出目录并用相对路径引用。Mermaid 可能异步渲染，旁边的放大按钮也可能是 SVG；如观察到 `svg[role*="graphics-document"]` 可用它辅助定位，但不能把该选择器当成永久契约，也不能把按钮图标算作图表。
- SVG 使用 `XMLSerializer` 序列化，保留命名空间和 `foreignObject` 等实际内容，再以 SVG/XML 解析器检查可解析性。HTML `outerHTML` 可能含未按 XML 闭合的 `<br>`，不能直接作为 SVG 文件保存，也不能靠全局替换标签修补 XML。解析通过后仍要打开或渲染资源，确认文字和图形可读；XML 合法本身不能证明图表完整。
- 核对 Markdown 引用的本地资源确实存在且能读取。普通图片可保留绝对远程 URL，但需说明此导出依赖网络，不是完整离线镜像。
- 图表缺失、资源不可读或结构丢失必须记录到对应章节；不能凭视觉猜写，也不能静默忽略。仅正文文本落盘而图表仍缺失的章节保持 `failed`。

## 逐章回读与内容比对

按主流程约定的正文路径写入后回读，将实际文件与当前章节的原文或文章 DOM 逐章对照。只有身份和内容都通过，才能更新为 `saved`。文件存在、长度接近、工具退出成功或正文哈希相同，都不能替代内容验收。

1. 核对源 URL、slug、仓库、正文语言、可见版本、标题与目录激活项。确认文件没有混入上一章、错误页或页面界面内容。
2. 比较首段和末段正文，排除只保存首屏、截断尾部或加载占位符的情况。首尾必须来自文章内容，不能用导出元数据充数。
3. 按原顺序逐块核对标题、段落、列表项、表格单元格和代码。数量只是辅助信号，还须比较各块内容；一般文字可忽略转换引入的空白和 Markdown 标记差异，代码空白、表格对应关系和公式内容不能因此放宽。
4. 对照折叠区标题及内部块；KaTeX 按 TeX 源码比对一次，避免重复层造成误报。逐一确认 Mermaid 源码或图像资源、说明与引用，不能只核对图表总数。
5. 全部章节保存后，只把通过验收的已导出章节之间的正文链接改为对应本地相对路径；锚点须核对目标标题，无法保证时保留源链接。其他链接保持绝对源 URL，章节来源信息仍保留源 URL，不改代码示例中的 URL。

单章失败可继续其他章节，但正文或图表缺失未解决前，只能报告部分完成。结束前回读首章、末章及含表格、代码、图表的代表章节；这一步不能取代前面的逐章比对。只报告实际覆盖的结构和版本，导出时间不能证明站点索引日期或仓库代码的新旧。

## 提取规则失效后的探索与修复

### 先区分访问失败与结构变化

504、登录未完成、访问限制、生成排队或正文尚未加载，都不足以证明 DOM/API 结构改变。先确认当前页面状态、仓库和目标章，遵守主流程的登录交接、等待与有限重试规则；访问仍失败时保留实际错误和未完成项，不能用“规则升级”绕过访问问题或降低正文验收。

当页面确实可读，而旧定位、数据解码或转换规则不能得到对应正文时，再检查实际差异。

### 只观察已授权的读取来源

可用当前环境的通用浏览器能力，观察当前授权页面的 DOM、公开 HTML 数据、公开文档化 API，以及该页面实际发出的读取请求和允许读取的响应。先从文章、目录和页面已有数据定位；对请求只保留定位所需的公开方法、地址与响应结构，去掉敏感参数和头部。

不猜测或枚举未授权接口，不把观察到一个请求扩大为遍历其他接口的授权；不提取 cookie、token、存储中的凭据或登录账号信息。DOM 读取和 JSON 解码只处理数据，不能把页面 script 或响应字符串作为程序执行。仅当当前观察仍支持 Next/slug 模式时才沿用对应分支，不让框架名称代替证据。

### 修补维护源码并实际验证

1. 定位失效处：正文容器是否换位、载荷封装/slug 是否改变、返回是否截断、折叠区是否遗漏，或转换器是否丢失某类块。用公开来源 URL、DOM 节点/数据字段、公开 API 文档位置或已观察请求的无敏感信息定位说明差异；不要保存整份页面数据作为规则。
2. 从当前 skill 的安装来源或源码 checkout 定位可写的维护源码，在原规则或本引用文档中做必要修复；本技能的维护来源为 [MC0571/MC-SKILLS](https://github.com/MC0571/MC-SKILLS) 中的 `skills/zread-wiki-export/`。用户维护的独立 skill 副本可以就地修复；包管理的副本先修复维护源码，再按安装环境支持的方式同步。来源不可写时准备可审阅补丁并报告限制，不改安装配置或另存一套互相冲突的规则。保存目录配置不负责定位 skill 源码。
3. 修复后必须实际重新提取、落盘并回读受影响章节，按前文核对源身份、首尾及正文块。公共提取路径改变时，重新核对本轮使用该路径的所有章节；同时覆盖首末章和受影响的代码、表格、Mermaid/SVG、KaTeX、折叠区等实际结构。页面没有出现或本轮未能检查的结构须记为未覆盖，不能凭静态检查就宣布提取已修复。
4. 将可复用结论就地写回维护源码：保留公开来源定位、适用的结构条件、实际验证覆盖与尚存限制；只维护当前有效规则，不累加逐轮历史验证记录。不得写入机器路径、账号、凭据、用户配置值或用户导出的正文、资源与运行数据。具体导出状态继续由该次索引维护。
5. 若要共享修复，遵循主技能的 PR 准备、展示及用户同意流程。补丁只包含通用提取方法与验证，不混入用户导出正文、资源、索引或配置。

修复不能把缺失结构改称可忽略，不能用摘要补正文，也不能将仍受阻的章节标为成功。无法完成实际核对时，保留补丁与限制，明确说明规则修复尚未验证。
