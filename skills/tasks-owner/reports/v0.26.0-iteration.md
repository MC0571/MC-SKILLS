# PMO / Tasks Owner 协作成本迭代

状态：候选实现、独立审查与本地验证完成。版本：Tasks Owner 0.26.0、PMO 0.12.0，共享合同 2.0.0。
本文件承载已确认方案与验证结果，不另建平行状态源。

## 目标与边界

保留 PMO 对整体目标的持续责任、Owner 对明确范围的交付责任，减少重复判断、固定握手与人为等待。
保留验收、真实写入归属、权限、必要验证和高风险独立审查。
本次修改成对候选、共享合同、校验器和回归；不热迁移业务任务或覆盖已安装版本与现有成果。

## 变更与验收

1. Owner 默认直接执行，仅有独立收益时委派，一次说明完整范围与边界。
2. 删除固定握手和修复限额，依据范围/风险/新证据决定继续或重新设计。
3. 区分开始、等待、交付证据；高风险先调查与计划，实现后验证。
4. 合并适用验证来源，明确逐项覆盖；直接委任可无全局取舍权。
5. 定向回读、真实 terminal 优先、重复结果不重复派工。
6. 单一负责人维护最小恢复索引，不把 receipt/CAS/TTL 当确定性运行时。
7. 运行配置归宿主；反馈需要已有明确授权，canonical 身份不自动扩权。

删除已不再用于当前校验的旧关键词配置、119 条旧输出样例、配套模拟数据及其生成的盲审报告。
这些文件包含已废弃的固定模型、握手和修复预算期望；历史版本可从 Git 回读，历史评测记录保留。

同步文档、合同与两侧回放，更新版本及生成目录，再验证成对产物、独立场景并提交 PR。
回归覆盖：直接/委派、共享/独立写入、连续必要修复/越界、遗漏/重复完成及后继、
无变化复用/变化失效、批次完成/整体未完成；关键错误做负向变异和前后结果核对。

## 证据边界与后续

JSONL 只证明给定事实下的决策语义，不证明真实消息送达、原子更新或自动唤醒。
隔离实测记录实际工具行为；无对照数据不报告效率百分比。
历史 HotCP 样本解释已观察失败，相邻合并间隔不当净响应延迟。

正式发布、安装配对更新与业务持续成本对比，沿用既有发布/授权流程。
迁移先回读活动任务/工作树、继承授权和有效证据，在安全边界切换，不为新协议重开活动 writer。
