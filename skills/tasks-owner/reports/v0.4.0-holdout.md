## 结果

### PMO 同周期多动作

- 任务 locator：`/root/holdout_pmo_cycle`。
- 输入：A 已合并可收口；合并使旧依赖失效并产生新 head；B 已可开始；另有不影响 B 的产品取舍需用户决定。
- 首次输出：正确判为 `partially_blocked`，但把同一用户决策同时记为请求决策和有证据等待。
- 修订：在事件合同中明确，请求用户决策已经包含该范围的等待与恢复条件，同一差距不得重复记等待。
- 无答案复跑：按顺序返回 `closeout_unit → correct_drift → route_delta → create_or_wake_owner → request_user_decision`；
  B 与无冲突路径继续，只暂停依赖该取舍的范围。
- 独立判定：通过。首次真实歧义已形成有界修订，并由同一输入复跑证明消除。

### Skill 选择与近邻拒绝

- 任务 locator：`/root/holdout_routing`。
- 输入：多 Unit 仓库目标、PMO 委任的单一 Work Item、一次性函数修复、只读里程碑差距分析、PMO Skill 自身维护。
- 实际输出：依次选择 `pmo`、`tasks-owner`、`neither`、`pmo`、`neither`；没有把一次性实现或 Skill 维护吸入长期 Owner。
- 独立判定：通过。用户直接委任与 PMO 准入都进入同一 Unit Owner，PMO 仅处理多 Unit 目标或其只读全局分析。

### 系统性闭包缺失

- 任务 locator：`/root/holdout_owner_closure`。
- 输入：恢复授权不变量覆盖默认恢复、旧迁移和替代存储，但当前只有默认恢复证据；branch、head、reviewer 变化，
  产品出口、不变量和 ownership 未变。
- 实际输出：保持同一 Unit/收敛链；writer 不得开始；必须补齐旧迁移、替代存储及直接副作用面的正向、负向、
  顺序与失败零写入证据，再刷新当前版本的准入和审查证据。
- 独立判定：通过。实现载体变化没有重置 Unit，缺闭包时在 writer 前失败。

### 系统性闭包完整

- 任务 locator：`/root/holdout_closure_positive`。
- 输入：所有恢复、迁移、替代实现、adapter/codec 和副作用面均有准确代码 locator、正负证据、授权先于写入及
  失败无副作用证据；合同、运行、工作树和 START 握手有效。
- 实际输出：writer 可以开始；三个入口应组成一个紧密批次、一个稳定 Unit/writer/收敛链。只有出现独立价值、
  ownership、真实 hard dependency 或独立回滚证据时才可拆分；阶段性收敛还需顺序、累计矩阵、证据失效规则和
  最终 exact-main 收敛点。
- 独立判定：通过。完整闭包不会被错误阻塞，也不会按调用路径制造多条收敛链。

### 低频复盘与反馈授权

- 输入：两个项目复现同一 Tasks Owner 合同缺口；当前项目仍有安全产品修复；没有跨仓库反馈授权，也不知道是否已有
  同根 Issue。
- 实际输出：先完成产品恢复和后继，再形成去重候选；无授权且未完成搜索时不写 Issue/comment，状态保持
  `candidate`，无法安全披露时为 `deferred_private`；保存稳定 fingerprint、来源、产品恢复、候选、授权、提交与
  恢复 locator；禁止自动修改、安装、更新、重载或发布本机 Skill。
- 独立判定：通过。反馈没有抢占产品动作，没有越权写入，也没有触发 Skill 自修改。
