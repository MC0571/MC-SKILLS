# 按动作核验证据

## 运行能力

用当前工具 schema、返回值与工作区核实下一动作需要的身份、载体、权限和能力。
只检查实际使用或明确要求的能力；模型/推理强度默认继承宿主配置。
创建前确认工具能表达所需载体/权限，创建后用真实返回值绑定身份。
两个自填且相同的字符串不证明宿主能力，行为只读不等于 sandbox 强隔离。
必要能力缺失只阻相关动作；同 schema/环境/授权下已确认失败先复用，相关条件变化后再重试。

## 三个阶段

| 阶段 | 需要的证据 |
|---|---|
| 开始实施 | 范围/授权、真实位置、写入归属、必需依赖；适用高风险调查与覆盖计划 |
| 等待任务 | 真实任务身份、活动状态、宿主等待或可靠持久唤醒路径 |
| 交付/合并/发布 | 相关 writer 停止，实际验收/检查结果、必要独立审查和该动作授权 |

高风险计划指出不变量、入口/生命周期、实现变体、先后顺序与失败行为。
共享合同 `status: planned` 表示调查与验证计划已形成；检查定位指向可执行计划，不是通过声明。
实现后填写真实结果，适用面全部验证后才是 `verified`；不适用面给出依据。
新增遗漏面、验收或相关代码变化只使受影响计划/证据失效。
同一不变量多入口失败时扩大到相关入口，普通局部任务不强制矩阵。

## 验证要求

收集全部适用来源：用户、Issue、仓库 AGENTS/配置、Skill 默认，
以及 branch protection、security 和 release 合同；按 product/merge/release 阶段合并去重。
Issue 存在不豁免仓库检查；优先级只用于明确冲突，不能“命中即停止”。

豁免定位具体来源、具体 check 和有权覆盖的明确授权。
机器场景 overrides 绑定已回读用户来源；branch protection/security 强制要求不能靠文本豁免，
发布仍需 release 合同要求。某检查没写进 Issue 不表示可省略。

结果绑定变更内容、验收和环境，三者及证据位置未变可复用；
当前 SHA 的 required checks、PR 元数据及独立审查仍按仓库规则核验。
额外且不影响本批验收/不变量的基线失败进入已有 backlog，不冒充本批通过或扩大范围。

## 交付与审查

先自查验收、diff、范围、适用检查和相关副作用路径，再进行必要独立审查。
高风险、高影响或重要不确定性使用未参与实现的审查者；
普通低风险工作按仓库要求和风险选择验证，不默认再造 reviewer/cleanup 任务链。

审查绑定实际版本、相关完整 diff、需求与验证证据，审查者不修改被审内容。
修改后刷新检查，复审需要独立保证的部分；按 [scope-integrity.md](scope-integrity.md) 处理 finding。
产品验收、合并、发布分别判断，单个 commit、CI、merge 或任务 final 不证明整体目标完成。
