# 等待与恢复

Heartbeat 只负责已授权唤醒和漏事件恢复，不是审批器或事实数据库。
相同用途更新已有 Automation，遵循既定周期和通知偏好，不为每个任务再建监控。

## 最小索引

当前 Owner 单独维护目标/授权定位、活动任务定位、已消费结果标识和下一动作/等待条件；
有必要时保留宿主提供的每来源游标。实现证据留在原位置，索引只引用。
不复制 Issue、对话或全项目状态，不用手填 CAS、receipt、revision 声称原子性。

唤醒先观察准确来源，无变化且证据有效时结束，不重读整个项目或重复派工。
有变化核验对应任务、依赖和后继；来源冲突或影响未知才扩大到受影响范围。

## 事件恢复

最新真实 terminal 覆盖旧 checkpoint 的 active；核验后立即处理可执行后继。
一次多任务等待返回首个结果，不证明其他来源已消费；按来源与实际 cursor 分别处理。
重复结果用任务身份/结果版本识别，后继已存在则复用。

投递不确定先回读目标。缺事件、网络失败或索引缺失时定向恢复，
不把“没读到”当“没有”，也不宣称人工记录保证 exactly-once。
目前不需要并发写索引；实际出现时先用宿主单一归属或现有原子存储能力。

原生子任务依赖父任务等待时保持宿主等待；
App 异步任务确有持久唤醒能力与授权时才可留待恢复。
活动 writer 允许等待，合并、发布和相关资产删除前再核验其停止。
