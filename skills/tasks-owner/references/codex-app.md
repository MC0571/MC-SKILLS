# Codex App 实际能力

以当前宿主暴露的 schema 和返回值为准，不固化模型名、推理强度、并发数或重试次数。
PMO/Owner 继承运行配置；用户明确指定时核验实际支持与执行情况。

## 执行与消息

- Owner 默认本地执行，有价值的独立工作可用原生 Subagent，使用真实 Agent 身份和宿主完成等待。
- 用户明确要求独立任务才使用 `create_thread`；已有任务用准确 ID 继续/读取，不靠标题推断身份。
- `send_message_to_thread` 投递，`read_thread` 读取，`wait_threads` 等待；后两者不等于已发消息。
- 创建未就绪时不把 `clientThreadId` 当正式 `threadId`。
- `wait_threads` 可在首个完成时返回；分别保留来源 cursor，只消费已观察结果。
- 不假定工具返回 message ID、模型或全部任务输出。必要时定向回读，不把宿主未提供的字段设为固定握手门。

原生 Agent 按宿主要求维持父任务等待；App 持久任务需要实际唤醒能力和既定授权。
没有持久唤醒能力时不能承诺结束回合后自动继续。给其他人的外部消息需要明确授权。

## 按动作检查

写入前核对真实 cwd/worktree、Git 状态、唯一归属与权限，不检查未使用的监控/取消/外部 API。
明确要求的隔离、模型或审批边界无法实现时只隔离相关动作，不静默换配置、重启或扩权。
创建或投递不确定先回读目标，避免重复副作用；相同条件下已确认失败不反复探测。
取消能力确实可用且在授权内则自行取消并回读，“cancel 已请求”不证明已停止或未发生外部写入。

## 验证与反馈

本地检查实际运行；Hosted checks 按 [runtime-and-review-evidence.md](runtime-and-review-evidence.md)
合并适用要求。宿主与 GitHub 事实不能由索引自报代替。

反馈目标由共享合同定位；工具可用和 canonical 身份不产生写入授权。
沿用用户已明确授予的动作/目标范围，一次授权持续有效，无需每条重问；缺授权则保留脱敏候选。

先恢复产品，核对授权、目标、内容与重复记录；同根因用现有 Issue。
搜索不完整或投递不确定先回读，成功用真实 locator 确认，失败保留可复制草案。
人工表单与 API body 用共享字段，不假定 API 自动套表单。
不上传凭据、完整对话/环境或未授权业务信息；反馈不授权修改、安装、重载或发布 Skill。
