# 委派与交付接口

## 一次委派

Owner 本地执行使用已有目标和授权，无需给自己生成合同或握手。委派一次说明：

- 结果、验收及权威定位；
- 允许和排除范围、写入位置及唯一负责方；
- 已授权动作、真实前置依赖、验证要求；
- 返回位置，以及越界或阻塞时应报告的事实。

跨 PMO 字段见 [dev-orchestration-contract.json](dev-orchestration-contract.json)，引用已有事实，
不在 Issue、索引和消息中维护独立副本。工具返回真实任务身份和载体即可绑定委派，
必要前置条件满足后直接执行。创建尚未就绪时等待真实身份，不将占位 ID 传入后续工具。
无需固定的确认、路由确认、释放、释放确认、START、STARTED 序列。

## 写入归属

写入前确认目标/授权、正确任务分支与工作区及其现有修改、相关载体没有另一个 writer。
只核验实际使用或明确要求的运行能力；本地执行不因缺少任务、监控或取消能力受阻。
高风险覆盖按 [runtime-and-review-evidence.md](runtime-and-review-evidence.md) 分阶段检查。

## 结果与事件

结果说明实际完成、证据、修改范围、未决风险和下一动作；不另要 ACK 重复工具已返回的信息。
发送成功不证明工作完成，结果自报不代替验收。
用宿主事件标识或“任务身份 + 实际结果版本”识别已消费结果，避免重复派发或外部写入。

只有可执行后继或重要变化才发送必要消息。投递不确定时先查询准确目标，
确认尚未执行后再决定重试；无证据则保留“不确定”，不伪造回执。
PMO 正常可见路径是一份委派和一次交付，期间只上报影响其决策的变化。

## 交付

确认变更满足验收、没有越界，相关 writer 已结束或由宿主证明撤销写权限，
再完成适用验证、必要独立审查和 PR 元数据检查。
修改后刷新对应证据；范围内必要修复可以继续，不靠改任务身份绕开问题。

合并、发布、关闭外部事项和删除重要资产各自遵循已有授权。
Owner 回读产品结果、目标版本与外部状态，更新权威事实，再判断批次与整体是否完成。
按 [cleanup.md](cleanup.md) 清理或明确保留现场，不强制另建清理任务。
