# Tasks Owner v0.19 批次 admission 与审查收敛

## 变更范围

- 基础设施、安全或平台 Work Item 只有在写明首个真实消费者、最小消费者可验证增量、逐条安全开始反事实、
  fixture/recorded contract 不足原因和延期边界后，才能成为产品工作的 hard blocker。`blocked-by` 只记录
  GitHub 关系；能安全先行的薄切片必须 admission，真实上游只阻 residual integration。
- `critical_path_width=1` 连续两个 `truth_digest/state_digest` 未变化的控制周期后，Owner 必须实际重分类
  依赖、admission 并行 tight batch，或给出逐项不可并行证据与 wake condition。
- 每个 review finding 先经过 disposition admission；severity 只排序。`fix_now` 必须映射当前验收/不变量
  或有现实 P0/P1 风险证据、不得扩大生产/权限/运行边界，且延期会使当前结果失真或不安全。
- 同一 `task_key + scope_revision` 在首次 fresh review 后只允许一个 finding-driven 写入回合；reviewer、
  blocker、文件、head/commit 和 execution generation 均不能重置。只有有证据的 shrink/split/reassign 形成
  更窄 task key 后才有新预算。

## 结构化与语义证据

- `evals/trajectory_cases.jsonl` 共 24 条，覆盖 6 个规则的 pass/fail；其中 12 条覆盖 review disposition、
  多 finding 单轮修复、跨 reviewer/blocker/generation 的第二轮拒绝、真实 scope reset、carrier、
  `user_decision` locator 和未处理 finding。标准库 replay 与 mutation self-test 均通过。
- `evals/output/cases.jsonl` 共 119 条；新增 8 条 v0.19 recorded fixtures，覆盖伪 hard、recorded-contract
  薄切片、真实 safety hard、合法 tight batch、超大平台 shrink、first-slice 缺字段，以及单通道两周期的
  action/no-action。
- 外部案例来源为 ScorAce [#348](https://github.com/scoracecom/ScorAce/issues/348) 与
  [#279](https://github.com/scoracecom/ScorAce/issues/279) 的只读快照；回归数据使用匿名 fixture locator，
  不修改外部 Issue truth。

## 证据边界与未纳入范围

- 上述结果只证明本地 deterministic replay、recorded fixture 与仓库契约一致；provider/model replay、
  人工盲审和真实生产运行仍为 `missing evidence`，未被 fixture 冒充。
- 本批不修改真实用户 `~/.codex`，不创建 GitHub Release/tag，不新增运行态数据库，也不重构无关的
  delivery、cleanup 或 Heartbeat 机制。
- v0.18 历史记录保持原样；v0.19 的安装一致性、exact-head review 与 hosted CI 在本批 closeout 单独回读。
