# Tasks Owner v0.18 生命周期收敛、自适应唤醒与结构化轨迹

## 变更范围

- `related_execution_units` 将任务线程、native/App writer、reviewer 和 cleanup Subagent 绑定到 generation、
  宿主状态、写权限、completion locator 与 Owner consumption；发布前新增 `convergence_writer_quiescence`。
- merge、cleanup 和 `COMPLETED` 之前，writer 必须 terminal，或具备宿主可回读的 quiesce ACK 与撤权证据；门禁通过后
  重读 diff、文件哈希和 exact head，再执行 fresh review。cleanup 只能由专用 Luna/max、`fork_turns: none` Subagent
  执行，Owner 独立验收。
- direct 仅承载当前回合可完成的有界工作；Owner 以不超过 60 秒一段的 native wait 消费 completion。长时工作使用
  App task 的 `codex_app__send_message_to_thread` 唤醒，Heartbeat 仅用于漏消费恢复。
- canonical event 与 delivery state 严格分离；成功取得 message locator 后清除 pending/failure，单向推进到 consumed。
- 连续 3 个 eligible 稳定等待 Heartbeat 周期后，Owner 可实际将周期加倍，最长 24 小时；新事件或 Owner action 恢复
  基础周期，用户 `fixed_interval/no_backoff` 优先。

## 结构化轨迹证据

`evals/trajectory_cases.jsonl` 保存最小事实事件（`seq/turn/actor/kind/locator/tool/args/facts`），由
`scripts/validate-tasks-owner-trajectories.py` 以标准库重放，不依赖关键词。覆盖 canonical delivery、writer quiescence、
cleanup terminal/consumed、direct bounded wait 和 Heartbeat backoff/restore 的正负轨迹；`expected` 只比较最终 verdict。
`source_kind=recorded_fixture` 仅表示本地确定性验证，不冒充 provider/model 或生产运行时证据；可回读的真实轨迹使用
`source_kind=live_readback`。

`validate-repository.py` 默认接入轨迹校验，`--self-test` 额外执行删除 terminal、writer running、错误 cleanup tool 和
乱序等 mutation，确保规则翻转会失败。
