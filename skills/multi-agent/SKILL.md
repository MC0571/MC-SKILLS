# 多 Agent 协作

仅在任务需要且已获准使用多 Agent 协作时应用。使用本技能不扩大代码、GitHub、合并或发布授权；用户和仓库规则仍决定工作范围与停止位置。

## 职责

- **Agent**：负责一个特定目标，目标与责任范围由用户或委派者明确。每个目标只有一个负责人，在授权范围内负责目标与范围、关键判断、依赖和共享状态、接口及仓库不变量、任务分配、冲突裁决、集成、最终验收与合并决定。可将子目标委派给另一个 Agent，由其持续推进到交付并向委派者交接；跨目标决定由覆盖该范围的负责人裁决。原则上不承担已委派的实质实现。
- **执行 subagent**：完成小、执行动作明确、可单独验收的有限任务。按决策范围和可验证程度确定任务大小；必要输入、执行动作、修改范围和验收标准由派发者明确。可自主作出局部实现判断；难度较大的方案判断，以及影响目标范围、架构、共享契约或验收标准的决定，交回目标负责人。完成自身局部验证后交接结果，派发者仍对结果负责。
- **Reviewer**：可以是 subagent，也可以是独立任务 Agent；独立审查，不参与被审内容的实现。自主检查正确性、回归、契约与仓库不变量、测试覆盖、边界和副作用，返回有依据的 findings，交由目标负责人裁决并组织修正。若 Reviewer 修改了代码，该修改须由另一独立 Reviewer 或目标负责人审查。

同一整体交付只有一位集成负责人，统一负责最终集成、验收与合并决定；GitHub 写入仅由该负责人执行，子目标委派不自动转移这些职责。用户明确授权的 PR review 由完成该次审查的 Reviewer 本人提交。

subagent 不得继续派生下一层 subagent；需要进一步拆分时向派发者交接建议。

## 模型

- **Agent**：默认使用 `gpt-6.1-sol` / `high`。
- **执行 subagent**：首选 DeepSeek-v4.1-flash / `max`；兜底使用 `gpt-6-luna` / `max`。
- **Reviewer**：使用 `gpt-6-astra` / `low`，无论采用 subagent 还是独立任务聊天，均按此审查职责路由。
- 按实际职责分类，不靠 Agent 名称规避路由，也不静默继承派发者模型。指定模型不可用时，说明受影响的委派，不能悄悄换模型。

## 分解、派发与集成

1. Agent 理解自己负责的目标与关键约束，识别关键未知、依赖与可并行工作单元。目标负责人根据证据决定任务边界、跨单元接口与关键方案；可将输入和动作明确的事实收集、实现、调试或验证任务交给执行 subagent。独立、低冲突、可单独验证的工作优先并行；紧密耦合、共享文件冲突或接口尚未稳定时串行，不为增加 Agent 数机械拆分。每个实质实现单元只有一个 owner，优化最短关键路径。
2. 每项委派写明目标、范围、仓库基线、相关约束、禁止修改范围（如有）和验收标准。传递已知决定、依赖、必要输入和预期产出；派发执行 subagent 时明确执行动作。影响范围、共享契约或验收的未知返回目标负责人裁决。执行 subagent 报告修改或发现、实际检查结果及剩余风险；最终集成决定留给负责该交付的 Agent。
3. 负责交付的 Agent 核对返回的实际改动与证据，整合为一个候选；每轮返回后重估新的安全并行机会。优先在候选初步收敛后安排独立审查，不机械地为每个执行 subagent 配一个 Reviewer；高风险区域可单独加审。
4. 执行 subagent 与 Reviewer 意见不一致时，目标负责人依据目标、有效规格、实际代码、测试、接口契约、仓库不变量及可复现证据裁决，不按模型强弱或作者身份裁决。

## 会话复用

可以复用已有 subagent 会话，但每个新任务重新注入目标、边界、仓库基线、约束和已知决定。任务域明显变化、上下文污染或错误假设持续影响判断时，启用新会话。

## 派发入口与按需参考

- 持续负责完整目标的 Agent 使用独立任务聊天，有限执行任务使用 subagent；不要因权限故障把持续负责人降成不能再派生的 subagent。创建或 Fork 独立聊天须有用户明确委派依据。
- 非 OpenAI provider（包括 `opencode-go/*`、`workbuddy/*`）的 subagent 必须通过 `multi_agent_v1` 派发：使用其 `spawn_agent` 创建，并使用同一工具族的 `send_input`、`wait_agent`、`close_agent` 继续、等待和关闭会话。不得使用旧版 `collaboration.spawn_agent`、`collaboration.followup_task` 等入口派发或续派这些 provider。
- 当前上下文未提供 `multi_agent_v1` 时，说明受影响的委派和入口限制，再按既有模型优先级处理可用的回退；不得尝试旧入口代替，也不得将旧入口失败认定为模型忽略任务。模型元数据列表未列出某个 provider，不足以断言该 provider 不可用。
- 创建或替换独立任务聊天前，读取并遵循 [Codex 权限继承、启动核验与故障处理](references/codex-permissions.md)。
- 审查或发布 PR review 前，读取并遵循 [PR 审查范围、版本绑定与发布流程](references/pr-review.md)。
