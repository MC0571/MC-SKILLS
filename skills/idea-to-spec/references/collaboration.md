# Owner 委派与整合

仅在实际委派时由 Owner 加载。Owner 保持唯一集成责任，主文件的短共享契约、推进门槛和角色归属继续适用；本文件不作为工作者的共同必读材料。

## 按依赖划分与派发

- 先明确各专题要回答的问题、依据、依赖决定、产物和完成条件，留在会话或既有跟踪位置，不另建任务台账。按问题与依赖划分，不按文档页数固定配置 Agent。
- 紧密依赖的工作串行；只有输入稳定、边界清楚且写入不重叠的专题适合并行。共享概念或共同契约先由其负责角色提出、Owner 整合，不让多个工作者各自决定同一规则。探索期可委派具体可行性核查，但候选技术方案不能冒充已选架构。
- 使用当前环境实际可用的 subagent 工具，遵守实际模型、资源及并发约束，不要求特定供应商、模型或插件，不凭角色数量承诺并行。禁止工作者再派生，不为内部子任务创建用户侧聊天。
- 明确每个工作者可写的文件或章节；共享文档由 Owner 整合。允许直接写入时指定互不重叠的边界，越界的上游或相邻修改以建议返回，不自行覆盖。委派不扩大代码、外部操作或文件修改授权。
- 用户禁用委派或工具不可用时，Owner 串行承担必要角色并如实自审，说明未获独立审查及其具体影响，继续其他可完成工作，不能把自审称为独立审查。

## 输入快照与角色提示词

Owner 只加载本轮需要的角色参考，向工作者传入主文件的短共享契约、适用推进门槛与必要角色提示词；工作者无需读取主文件全文，也不读取本 Owner 手册或全部角色参考。产品、架构、Spec、实施分别使用对应角色提示词；只有需要审查候选时才读取 [review.md](review.md)，并将审查提示词交给审查者。

输入包括原始要求及来源、有效决定与假设、相关上游章节、整体目录和必要的上下游契约。版本使用已有修订号、提交或明确原文快照；有未提交修改时提供可定位的工作区快照或差异，不能用旧提交号冒充当前输入。不灌入全部历史聊天，不建立版本服务。

按任务填写以下模板，删除不适用项，不发送未替换的占位符：

```text
角色与具体任务：{{本轮有界结果；探索、细化、实施或审查}}
范围与禁止事项：{{包含、不包含；可写路径/章节；禁止再派生}}
输入快照：{{原始要求与来源；相关材料位置、章节及版本/原文快照}}
有效基线：{{已有决定、约束、假设与待决项}}
必要上下游契约：{{共享概念、相邻边界、依赖与受影响使用方}}
产物位置与格式：{{文件或会话中的具体结果}}
完成条件：{{可检查的用户结果与本轮适用推进门槛}}
共享契约：{{传入主文件短共享契约}}
角色指令：{{本轮必要角色提示词}}
返回：所用输入版本、实际产物位置/修改、依据、新增选择、假设与待决项、
      实际检查及未执行项、上下游影响和越界修改建议。
```

## 回读、采纳与关闭

1. **回读实际产物**：Owner 直接读取候选或实际差异，不以工作者自报完成作为采纳依据。核对范围、新增设计选择、共享对象身份及单值/多值含义、上下游契约、假设和待决项，以及检查证据所对应的版本。
2. **整合为有效输入**：按依据采纳或退回具体修改，解决共享定义冲突，清理重复规则及失效交接提示。整合成可定位版本并核对适用推进门槛后，再交给依赖它的角色；过期快照的结果先检查受影响部分，不能直接沿用。普通取舍在既有授权内处理，不新增逐阶段用户审批。
3. **安排独立审查**：实质设计候选形成后，交给未参与编写的独立 subagent。小修订可聚焦受影响内容及其上下游，不为每页固定派审。审查者直接读取原始输入、当前候选和有关来源；本轮包含实施时还须提供关联代码、测试与实际运行证据，不能仅给作者摘要。
4. **裁决与返修**：Owner 按依据处理发现，向负责角色明确问题、影响、写入边界与完成条件。修订后补审新增修改及其对完整当前范围的影响，并补齐受影响检查；旧版本审查不能为新候选背书。需改变有效基线时按主入口的条件路由处理，不因委派自动加载变更参考。
5. **关闭与交付**：核对最终产物及必要验证，收取结果后结束已闲置的子 Agent。按本次范围报告实际完成、审查类型、未解决项和证据限制；关键未知只阻塞依赖它的部分。没有新信息时停止重复派发，不能用多轮共识、工具成功或文件生成代替完成。
