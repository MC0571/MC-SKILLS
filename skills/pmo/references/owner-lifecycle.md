# Owner 委任与恢复

在创建、唤醒、恢复、去重或结束 Owner 时读取。Owner 内部执行使用 `$tasks-owner`。

## 依赖和动作能力

首次实际执行前，定位当前可用的 `tasks-owner`，读取入口与 `references/dev-orchestration-contract.json`。核验主版本和当前委任所需能力；不维护第二份 schema。缺失或不兼容时先给分析和可审阅草案，实际需要执行时再询问安装或更新。

当前发布源为 `github:MC-and-his-Agents/MC-AGENT-KIT@main:skills/tasks-owner`，安装目标为用户 Skill 目录中的 `tasks-owner`。安装和覆盖更新须有用户授权；已授权的同一次安装不重复询问，更新后重新核验。请求、安装状态及所需能力未变化时复用结论。

使用宿主真实提供的创建、消息、等待和取消能力。用户明确指定的 runtime 是约束：按实际动作检查并尊重，不能静默降级。缺失无关 metadata 或默认配置线索，不阻塞已能证明安全的观察、结果核验或动作；已确认不符合用户要求时停止受影响的新执行并恢复原任务，其他范围继续。

## 一次完整委任

范围已有权威验收、开始条件成立、授权覆盖且没有同范围活动 Owner 时，向一个真实任务一次交付：

- 仓库、目标 ref、范围及验收定位；
- 产品目标与对总体结果的贡献、允许和排除范围；
- 工作位置、写入归属、相关真实依赖；
- 已有授权、用户保留决定及结果返回位置。

字段以共享合同 `pmo_admission` 为准，已有 Issue 或授权事实直接引用。Owner 能据此开始执行即可，无须 PMO 再确认 Owner 内部合同、释放、START 或 STARTED。工具返回可用任务身份后保存 locator；异步创建只返回临时身份时，先等待真实身份，再做依赖该身份的投递。

PMO 对 Codex App 独立任务的创建还必须满足宿主约束，包括用户明确要求创建独立任务。仅有分析请求或工具访问权不构成创建授权。适用时可复用已授权的 Owner。

普通单元只有一次 `pmo_admission` 和完成结果；中间只有改变全局判断的 `owner_sparse_delta`。Owner 直接实现或委派、同范围修复、CI、PR、合并和清理由 Owner 连续完成，PMO 不增加逐步审批。

局部 blocker 只需说明影响哪个动作、仍可做什么、谁处理及何时恢复。Owner 有剩余安全工作时继续；只有跨单元依赖、范围/归属变化或用户保留决定才上行。不存在固定审查修复轮数，重复根因和范围扩大触发方案复盘，不能靠新任务身份重置真实成本或授权限制。

## 运行和展示

以真实 task/thread locator、范围与当前工作判断 Owner 是否活动。标题、置顶是可选展示；支持且已授权时可设置，失败时记录展示未完成，不阻塞交付和总体状态。

长任务需要可用的恢复路径。宿主原生完成通知或 wait 已覆盖时无需为每个临时执行者创建 Heartbeat。确需跨回合恢复且已有 Automation 授权时，为负责长期范围的 Owner 创建或复用专属 Heartbeat；Owner 和 PMO 的 Heartbeat 不重复执行对方职责。恢复路径缺失影响脱离当前回合后的持续执行，不阻塞当前可完成的安全工作。

## 唤醒与恢复

只在新范围已就绪、相关依赖/验收变化、跨 Owner 冲突或存在可执行却停滞的动作时，精确唤醒对应 Owner。健康运行、重复完成消息、普通修复和无变化状态不唤醒。

恢复先回读该 Owner 最近的实际状态与相关结果。较新的完成、取消、取代或停止事实优先于旧 active checkpoint；不要据旧摘要先诊断、替换或中断。消息缺失时用定向任务/仓库回读恢复，不能把静默当作失败。

已授权同范围动作误入等待批准时，明确原授权和下一动作交回原 Owner。缺少真实权限、不可逆动作授权或产品决定则保留对应等待。恢复时保留 branch、worktree、PR 和未提交成果；PMO 不接管文件级修复。

无法确认原执行者停止相关写入时，不启动同载体替代者。工具能力未知时先查可用合同和实际状态；不是每个异常都要重新创建 Owner。

## 去重、完成和取消

用权威范围 locator 和真实任务身份去重，不按标题或摘要去重。冲突只暂停共享写入范围；选择有权且可定位的执行者，通知各 Owner 保留和交接成果，无冲突路径继续。

分别处理：

- `PR_MERGED`：一个增量已进入目标 ref，只更新受影响依赖；不能结束整个 Unit 或 Owner。
- `DELIVERY_UNIT_COMPLETED`：核验范围验收和剩余事项去向，释放已满足的依赖并启动后继。长期同域 Owner 仍可承担原委任范围的剩余工作。
- `OWNER_TERMINAL`、取消或取代：核验是否停止相关写入、成果是否已交付或保留、剩余范围是否有承接者，再移出活动归属。用户取消不授权删除成果。

结束后的专属 Automation 需暂停或删除并回读，避免重复执行；展示取消置顶按能力处理。若 Automation 无法停止，明确残留及恢复动作，不授权它继续写入。残留只影响相应范围，不阻止已无冲突后继。展示失败不回滚已核验产品完成。
