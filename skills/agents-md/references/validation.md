# 验证、加载与效果边界

## 四种证据必须分别报告

| 层级 | 本次能做什么 | 不能据此声称什么 |
|---|---|---|
| 静态核对 | 路径、命令定义、引用、作用域、别名与事实来源存在；比较删改前后约束 | 命令已运行、宿主已加载、Agent 表现提升 |
| 执行验证 | 在注明环境和代码状态中实际运行安全、相关的检查 | 所有平台/真实服务/未覆盖路径通过 |
| 加载验证 | 目标宿主实际报告或日志证明读取了哪些文件 | 读取后必然遵守，或别的客户端也会加载 |
| 行为对照 | 在可比、隔离的任务中观察决策与实际结果 | 少量样例证明普遍收益，或消除所有失败 |

缺失哪一层就写缺失哪一层。跳过、失败、不可执行和通过是不同结果。

## 静态检查

检查相对引用、实际任务入口、cwd、前置条件、生成源与输出；是否把现行规范和归档混合；父子规则是否重复或冲突；别名是否仍指向同一内容源。只读脚本可辅助盘点，不能理解自然语言义务。

仓库脚本名称与底层命令相似不代表等价。包装任务可能设置环境、执行另一测试运行器、限制工作目录或处理多个构建系统。核实定义后再写替代建议。

不得从 Markdown 中抽取代码块或命令字符串后直接执行。即使只想检查是否能运行，安装、生成、网络、凭据使用和破坏性步骤仍受已有授权约束。先读脚本，再选择最小相关检查。

## 加载验证

更改导入、符号链接、文件名、嵌套层级或目标客户端时，查看当前目标工具的官方说明和本地实际配置。普通 Markdown 链接只是导航，不等于自动导入。

Codex 的启动目录、用户级文件、`AGENTS.override.md`、备用文件名和累计大小限制都会影响实际指令链。嵌套文件不等于根目录启动后所有相关任务必然读到。为特殊工作保留显式阅读触发。

Claude Code 的 `@file` 导入是其宿主机制；不能推定其他客户端支持相同语法。对已有桥接先核实再改，不默认将所有 `CLAUDE.md` 替换成 `AGENTS.md`。

2026-09-30 核对的官方入口见本包 `research/sources.json`；这里只保存需要核对的因素，不把数值和语法冻结为跨工具标准。

没有目标客户端时可以检查文件结构，明确“未验证实际加载”。不要编造后台 resolved 模型、加载成功日志或宿主配置。

## 三项情境检查

1. **错误方案**：从实际风险选择一个错误动作，例如手改生成物、从根目录运行被禁止的测试、以跳过的真实服务用例宣告验证完成。指出规则是否能在动作前指导选择。
2. **正确方案**：选择一个正常目标以及实际存在的例外，确认规则不会要求无关重构、额外审批或无法满足的门槛。
3. **删除/迁移**：对重要删除找出失去的决策依据或阅读入口；确认确有替代而非只是字数减少。

只在草稿上推演属于人工检查，不要标记为 Agent 实测通过。

## 实际 Agent 对照方法

确需评估且宿主与权限可用时：

- 使用同一仓库快照和不同隔离工作区，保留原版与候选指令。
- 同样的任务、模型、推理配置、权限、工具和外部服务条件；每次采用新会话。
- 任务覆盖本次关键错误路径、正常路径与例外。只在必要时增加重复试验，报告样本数与偶然性。
- 观察实际读取的来源、选用入口、代码/文件/状态、测试结果、越界动作、额外工作量；不以“我遵守了规则”作为证据。
- 验证任务不应直接泄露期望答案，否则只是在测试复述。
- 原版已经足够时不声称改进；候选阻塞合法工作时修订或回退。

`evals/cases.json` 是可重建的合成场景与验收预期，不是行为结果。运行单元测试只验证辅助脚本；校验 JSON 只证明测试资料可解析。

## 本 SKILL 的维护检查

每次改动检查触发描述与边界是否一致，参考是否可达，脚本是否仍只读，测试是否覆盖改动。评估或实测不可用时交付清楚的限制，而不是以更多章节替代验证。
